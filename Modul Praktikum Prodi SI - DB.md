1. # **PERTEMUAN 1 \-  MODERN WORKFLOW: GIT & GITHUB** {#pertemuan-1---modern-workflow:-git-&-github}

   1. ## **Tujuan Intruksi Khusus**

Setelah menyelesaikan praktikum ini, praktikan diharapkan dapat:

1. Memahami konsep dasar Version Control System menggunakan Git.  
2. Membuat akun dan mengelola repositori pada platform GitHub.  
3. Melakukan instalasi dan konfigurasi awal Git pada komputer lokal.  
4. Menerapkan alur kerja (workflow) modern menggunakan perintah git clone, git add, git commit, git push, dan git pull.

   2. ## **Alat dan Bahan**

Alat dan bahan yang dibutuhkan pada praktikum ini sebagai berikut:

1. PC Desktop / Laptop  
2. Sistem Operasi Windows 8/10/11 (atau Mac/Linux)  
3. Aplikasi Git (Git Bash untuk Windows), *link download*: [git-scm.com](http://git-scm.com)   
4. Visual Studio Code, *link download*: [code.visualstudio.com](https://code.visualstudio.com/)  
5. Web Browser (Chrome, Firefox, Edge, dll)  
6. Koneksi Internet aktif  
7. Akun Email aktif untuk pendaftaran akun GitHub

   3. ## **Dasar Teori**

      1. Tentang Git dan GitHub

   **Git** adalah *Version Control System* (VCS) terdistribusi yang digunakan untuk melacak perubahan pada file proyek dan berkolaborasi dengan banyak orang. Git bekerja secara lokal di komputer pengembang.

   **GitHub** adalah layanan *cloud hosting* berbasis web untuk menyimpan repositori Git. Jika Git adalah mesinnya, maka GitHub adalah tempat kita menyimpan dan membagikan kode (*source code*) kita agar bisa diakses secara publik maupun privat, serta berkolaborasi dengan tim (*collaborators*).

      2. Siklus Kerja Dasar Git (Git Workflow)

   Dalam penggunaan sehari-hari, workflow modern untuk Git dan GitHub melibatkan beberapa perintah utama berikut:

1. **`git clone`**: Menggandakan (menyalin) repositori yang ada di GitHub ke dalam komputer lokal.  
2. **`git add`**: Menambahkan file yang baru dibuat atau diubah ke dalam *staging area* (area persiapan sebelum disimpan permanen).  
3. **`git commit`**: Menyimpan riwayat perubahan dari *staging area* secara permanen ke dalam Git lokal, dilengkapi dengan pesan (*commit message*).  
4. **`git push`**: Mengunggah *commit* yang ada di komputer lokal ke server GitHub.  
5. **`git pull`**: Mengambil (*download*) perubahan terbaru dari server GitHub ke komputer lokal, berguna ketika bekerja dalam tim dan ada anggota tim lain yang memperbarui kode.

   Dan masih ada banyak perintah lagi yang dapat anda pelajari di dokumentasi resminya di [https://git-scm.com/docs](https://git-scm.com/docs) 

   4. ## **Instruksi Modul**

      1. Membuat Akun GitHub  
1. Buka *web browser* dan kunjungi alamat [**github.com**](https://github.com/).  
2. Klik tombol **Sign up** di pojok kanan atas.  
3. Masukkan alamat email aktif Anda, buat *password* yang kuat, dan tentukan *username*.  
4. Lakukan verifikasi teka-teki visual (*captcha*) sesuai instruksi yang diminta (misal: memutar gambar hingga posisinya lurus).  
5. Buka kotak masuk email Anda, cari email dari GitHub, lalu klik tombol **Verify email address** atau masukkan kode OTP yang diberikan.  
6. Login kembali ke GitHub.

   

   

   2. Membuat Repositori Baru  
1. Pada halaman utama GitHub, klik ikon \+ di sudut kanan atas dan pilih New repository (atau klik tombol hijau Create repository).  
2. Isi form pembuatan repositori sebagai berikut:  
   1. **Repository name**: `personal-goal-belajar-git` (atau nama lain tanpa spasi).  
   2. **Description**: *Repositori untuk menyimpan rencana dan cita-cita ke depan.*  
   3. Pilih **Public** agar repositori bisa dilihat oleh orang lain.  
   4. Centang bagian **Add a README file** agar repositori Anda tidak kosong saat pertama kali dibuat.  
3. Klik tombol hijau **Create repository**.  
4. Repositori Anda telah berhasil dibuat. Salin URL repositori tersebut (contoh: `https://github.com/username/personal-goal-belajar-git.git`) dari tombol **Code**.  
   3. Melakukan Clone Repositori ke Lokal  
1. Buat sebuah folder baru di komputer Anda (misal: di drive `D:\PraktikumDB\XXXX`).  
2. Buka folder tersebut, klik kanan pada area kosong, lalu pilih **Open Git Bash here** (atau buka terminal melalui Visual Studio Code dan arahkan ke folder tersebut).  
3. Ketikkan perintah berikut untuk mengunduh repositori ke komputer lokal Anda (ganti URL dengan URL repositori Anda masing-masing):

`git clone https://github.com/username/personal-goal-belajar-git.git`

4. Masuk ke dalam folder yang baru saja di-*clone*:

`cd personal-goal-belajar-git`

4. Coba Git Add (Menambahkan File Baru)  
1. Buka folder `personal-goal-belajar-git` tersebut menggunakan Visual Studio Code.  
2. Buatlah satu file baru bernama `personal-goal.txt`  
3. Isi file tersebut dengan daftar goal, target, atau mimpi Anda di tahun ini (contoh: *1\. Konsisten masuk kuliah tanpa bolos; 2\. Mendapatkan nilai A di semua makul;*). Simpan file tersebut (`Ctrl+S`).  
4. Masuk ke terminal VS Code  
5. Ketikkan perintah berikut untuk memasukkan file ke dalam *staging area*:

`git add personal-goal.txt`  
(Tips: Jika ingin menambahkan semua file sekaligus, gunakan perintah `git add .`)

5. Melakukan Git Commit  
1. Setelah file berada di *staging area*, kita perlu merekam perubahan tersebut secara permanen di lokal dengan menyertakan pesan *commit*.  
2. Ketikkan perintah berikut di terminal:

`git commit -m "menambahkan file personal-goal.txt`

3. Tekan *Enter*. Akan muncul informasi bahwa file berhasil di-*commit* (tercatat *1 file changed, insertions*).  
   6. Melakukan Git Push  
1. Perubahan saat ini baru tersimpan di komputer lokal. Untuk mengunggahnya ke GitHub, gunakan perintah:

`git push origin main`

2. Catatan: Jika diminta login, masukkan kredensial GitHub Anda atau gunakan otentikasi browser  
3. Buka halaman repositori GitHub Anda di *browser* lalu *refresh*. File `personal-goal.txt`  kini sudah muncul di sana.  
   7. Melakukan Git Pull  
1. Untuk mensimulasikan `git pull`, kita akan mengubah file langsung dari GitHub.  
2. Di halaman repositori GitHub Anda, klik file `personal-goal.txt`, lalu klik ikon pensil (**Edit this file**).  
3. Tambahkan satu baris resolusi baru, lalu gulir ke bawah dan klik tombol hijau **Commit changes...**. Tulis pesan *commit* dan simpan.  
4. Sekarang, file di GitHub lebih *up-to-date* dibandingkan yang ada di komputer lokal Anda.  
5. Kembali ke terminal Visual Studio Code di komputer Anda, dan ketikkan perintah:

`git pull origin main`

6. Git akan mengunduh perubahan dari GitHub. Buka file `personal-goal.txt` di VS Code, dan Anda akan melihat baris baru yang ditambahkan dari GitHub tadi sudah muncul secara otomatis.

   5. ## **Latihan/Tugas**

1. Buatlah sebuah repositori baru secara publik di GitHub dengan format nama `[NIM]_TugasGit_DB`.  
2. Lakukan proses **Clone** ke komputer lokal Anda.  
3. Buat sebuah file `index.html` sederhana yang berisi biodata diri (Nama, NIM, Program Studi).  
4. Lakukan proses **Add**, **Commit**, dan **Push** file tersebut ke repositori Anda.  
5. Lakukan edit file `index.html` secara langsung melalui antarmuka GitHub (tambahkan Hobi Anda), lakukan *commit* di sana, lalu lakukan **Pull** ke komputer lokal Anda.  
6. Buatlah laporan praktikum yang berisi tangkapan layar (*screenshot*) histori *commit* dari repositori GitHub Anda yang membuktikan seluruh proses di atas telah dilakukan\! Jelaskan fungsi dari masing-masing perintah yang digunakan

## **2. PERTEMUAN 2 \- LARAVEL ARCHITECTURE & ROUTING** {#2.-pertemuan-2---laravel-architecture-&-routing}

### **2.1. Tujuan Instruksi Khusus** {#2.1.-tujuan-instruksi-khusus}

1. Memahami arsitektur dasar dan struktur folder pada framework Laravel.

3. Melakukan instalasi framework Laravel menggunakan Composer.  
4. Mengerti konsep dan cara kerja Routing di dalam Laravel (`routes/web.php`).  
5. Membuat rute dasar untuk menampilkan halaman statis dan sistem navigasi antar halaman.  
6. Memahami dan menerapkan styling antarmuka sederhana dengan Tailwind CSS.

   ### **2.2. Alat dan Bahan** {#2.2.-alat-dan-bahan}

Alat dan bahan yang dibutuhkan pada praktikum ini sebagai berikut:

1. PC Desktop / Laptop  
2. Sistem Operasi Windows 8/10/11  
3. Aplikasi **Laragon Full** (sudah mencakup Apache, MySQL, PHP, dan Composer bawaan), link unduh: laragon.org/download  
4. Visual Studio Code, link download: code.visualstudio.com  
5. Web Browser (Chrome, Firefox, Edge, dll)  
6. Koneksi Internet aktif

   ### **2.3. Dasar Teori** {#2.3.-dasar-teori}

#### 2.3.1. Tentang Laravel dan Arsitektur MVC

Laravel adalah framework aplikasi web berbasis PHP yang ekspresif dan elegan, dirancang untuk memudahkan proses pengembangan web secara cepat (Rapid Application Development). Laravel menggunakan pola arsitektur **Model-View-Controller (MVC)**:

* **Model**: Representasi data dan interaksi dengan database (menggunakan Eloquent ORM).  
* **View**: Tampilan antarmuka pengguna (User Interface), biasanya menggunakan Blade template engine.  
* **Controller**: Mengatur lalu lintas data (logika bisnis) antara Model dan View.

#### 2.3.2. Struktur Folder Laravel

Beberapa folder penting dalam Laravel yang harus diperhatikan:

* `app/`: Menyimpan inti kode aplikasi (seperti Models dan Controllers).  
* `public/`: Menyimpan file yang dapat diakses langsung oleh browser (CSS, JS, Gambar) serta file `index.php` sebagai titik masuk utama.  
* `resources/`: Menyimpan file raw yang belum di-compile dan file tampilan (Views).  
* `routes/`: Menyimpan definisi rute (URL) aplikasi. File `web.php` digunakan untuk rute web (antarmuka browser).

#### 2.3.3. Routing Dasar

Routing merupakan mekanisme untuk mencocokkan URL di browser dengan sebuah tindakan yang harus dilakukan oleh aplikasi. Di Laravel, semua request dari web browser dicatat dan diproses melalui routing sehingga navigasi di aplikasi menjadi lebih rapi.

#### 2.3.4. Pengenalan Tailwind CSS

Tailwind CSS adalah framework CSS *utility-first* yang sangat populer di industri modern web development karena kecepatan dan fleksibilitasnya. Alih-alih menulis aturan CSS di file terpisah dan membuat penamaan class satu per satu, kita dapat langsung menambahkan class *utility* bawaan Tailwind ke elemen HTML. Untuk tahap pembelajaran awal di Laravel, Tailwind dapat disisipkan secara instan dan cepat menggunakan metode CDN di file View.

Beberapa contoh kategori *utility class* dasar yang sering digunakan pada Tailwind CSS:

* **Spasi (Padding & Margin):** `p-4` (padding 1rem), `m-2` (margin 0.5rem), `px-4` (padding horizontal), `mt-4` (margin atas).  
* **Tipografi:** `text-center` (teks rata tengah), `text-xl` (ukuran teks besar), `font-bold` (teks tebal), `text-blue-600` (warna teks).  
* **Background & Border:** `bg-slate-100` (warna latar), `border border-gray-200` (garis tepi), `rounded-lg` (sudut membulat).  
* **Layouting:** `flex` (flexbox), `justify-center` (rata tengah horizontal), `items-center` (rata tengah vertikal).

  ### **2.4. Instruksi Modul** {#2.4.-instruksi-modul}

#### 2.4.1. Instalasi Lingkungan Laragon (termasuk Composer)

1. Buka web browser dan kunjungi `laragon.org/download`.  
2. Unduh versi **Laragon Full** (direkomendasikan untuk pengguna Windows) dan jalankan file installer tersebut mengikuti pengaturan *default* hingga instalasi selesai.  
3. Setelah selesai, buka aplikasi Laragon lalu klik tombol **Start All** untuk menyalakan servis web (Apache) dan *database* (MySQL).  
4. Klik opsi **Terminal** di antarmuka Laragon (atau klik kanan area kosong Laragon \-\> Laragon Terminal) untuk membuka jendela komando (Command Prompt khusus).  
5. Pada terminal Laragon yang terbuka, ketik `composer -v` lalu tekan Enter. Jika berhasil, akan muncul logo *text-art* bertuliskan Composer yang berarti *dependency manager* bawaan Laragon Anda siap digunakan.

#### 2.4.2. Instalasi Framework Laravel

1. Tetap buka jendela Terminal bawaan Laragon Anda. Biasanya terminal ini secara otomatis akan mengarahkan ke folder kerja Laragon (`C:\laragon\www\`).  
2. Jalankan perintah instalasi Laravel (kita asumsikan nama project yang akan diinstal adalah `laravel-app`):

`composer create-project laravel/laravel laravel-app`

3. Tunggu hingga proses *download* dependency paket dan scaffolding selesai.  
4. Masuk ke dalam direktori project yang baru saja dibuat dengan perintah: `cd laravel-app`.

#### 2.4.3. Menjalankan Server Development Lokal

1. Pastikan Anda masih berada di dalam direktori `laravel-app` pada Terminal.  
2. Jalankan server lokal bawaan Laravel dengan perintah:

`php artisan serve`

3. Buka web browser dan akses URL `http://127.0.0.1:8000` atau `http://localhost:8000`. Jika muncul halaman depan default Laravel, maka instalasi sukses\!

#### 2.4.4. Menambahkan Route Dasar

1. Buka folder `laravel-app` menggunakan Visual Studio Code.  
2. Buka file `routes/web.php`.  
3. Tambahkan rute baru untuk membuat halaman pendahuluan:

`Route::get('/tentang', function () {`

    `return '<h1>Ini adalah Halaman Tentang Aplikasi Event Hub</h1>';`

`});`

4. Buka browser dan akses alamat `http://localhost:8000/tentang`. Validasi pesan tampil pada layar browser.

#### 2.4.5. Membuat Route yang Menghubungkan ke View

1. Di Visual Studio Code, arahkan ke direktori `resources/views/`.  
2. Buat file baru dengan nama `contact.blade.php`.  
3. Isi dengan HTML sederhana yang memuat sebuah link yang kembali ke Home (`/`):

`<!DOCTYPE html>`

`<html>`

`<head><title>Halaman Kontak</title></head>`

`<body>`

    `<h1>Hubungi Kami</h1>`

    `<p>Email: admin@amikomeventhub.com</p>`

    `<a href="/">Kembali ke Home</a>`

`</body>`

`</html>`

4. Buka kembali file `routes/web.php` dan tambahkan rute untuk View tersebut:

`Route::get('/kontak', function () {`

    `return view('contact');`

`});`

5. Akses `http://localhost:8000/kontak` di web browser, lalu klik Link 'Kembali ke Home' untuk mencoba rutenya berjalan.

#### 2.4.6. Menerapkan Styling dengan Tailwind CSS (via CDN)

1. Buka kembali file `resources/views/contact.blade.php`.  
2. Tambahkan script CDN Tailwind di dalam tag `<head>` dan cobalah berikan *styling* yang lebih modern menggunakan class bawaan Tailwind:

`<!DOCTYPE html>`

`<html>`

`<head>`

    `<title>Halaman Kontak</title>`

    `<!-- Menyisipkan Tailwind CSS melalui CDN -->`

   ### **4.3. Dasar Teori** {#4.3.-dasar-teori}

#### 4.3.1. Pengenalan Migration

**Migration** adalah fitur dalam Laravel yang memungkinkan kita untuk mengelola struktur database secara terprogram menggunakan PHP. Hal ini membuat tim *developer* mudah untuk berbagi skema database dan menjaga konsistensi kolom di antara berbagai lingkungan (development, staging, production) tanpa harus mengekspor/mengimpor file `.sql`.

Saat menjalankan perintah *artisan* untuk membuat migration, Laravel akan men-*generate* sebuah file di folder `database/migrations/` dengan *timestamp*. File ini memiliki fungsi `up()` untuk membuat atau memodifikasi tabel, dan fungsi `down()` untuk menghapus atau mengembalikan modifikasi tersebut (Reverse/Rollback).

#### 4.3.2. Menyambungkan Aplikasi dengan Database (File `.env`)

Sebelum *merancang* database via Migration, Laravel harus terhubung dengan database lokal kita (misalnya MySQL atau MariaDB bawaan Laragon). Pengaturan konfigurasi koneksi ini tersimpan pada file `.env`. Kita cukup mengubah parameter `DB_DATABASE`, `DB_USERNAME`, dan `DB_PASSWORD`.

#### 4.3.3. Database Seeding & Faker

**Seeding** adalah proses pengisian data awal secara otomatis ke dalam database ketika tahap pengembangan. Fitur ini sangat berguna agar kita tidak perlu memasukkan data spesifik uji coba berulang kali secara manual dari *phpMyAdmin*.

Untuk menghasilkan baris data palsu dalam jumlah puluhan hingga ribuan (seperti nama, alamat, email, dll yang *random* namun masuk akal), PHP menyediakan sebuah *library* yang dinamakan **Faker**. Dalam Laravel, seringkali Seeding dipadukan dengan Factory dan Faker. Namun, untuk master data seperti akun admin panel, umumnya didefinisikan secara konstan di dalam method `run()` di Class Seeder.

### **5.1. Tujuan Instruksi Khusus** {#5.1.-tujuan-instruksi-khusus}

* Memahami fungsi dan efisiensi *Route Resource* pada ekosistem URL Laravel.

  ### **5.2. Alat dan Bahan** {#5.2.-alat-dan-bahan}

Alat dan bahan yang dibutuhkan pada praktikum ini sebagai berikut:

1. PC Desktop / Laptop

   ### **5.3. Dasar Teori** {#5.3.-dasar-teori}

#### 5.3.1. Eloquent ORM

**Eloquent** adalah *Object-Relational Mapper* (ORM) bawaan Laravel yang sangat efisien dan ekspresif. Setiap tabel pada basis data direpresentasikan melalui sebuah "Model" (misalnya: tabel `events` diwakili oleh Model `Event.php`). Dengan sistem ini, kita berinteraksi dengan basis data tanpa menggunakan kueri SQL murni, melainkan menggunakan metode bawaan Model seperti `Event::all()`, `Event::create()`, dan `$event->delete()`.

#### 5.3.2. Operasi CRUD

**CRUD** merupakan basis interaksi standar untuk sebuah tabel yang terdiri dari bagian-bagian berikut:

* **Create**: Memasukkan data baru ke dalam basis data (`Event::create($data)`).  
* **Read**: Menampilkan isi rekaman data pada layar (`Event::all()`, `Event::find($id)`).  
* **Update**: Memperbarui parameter data lama yang sudah tersimpan (`$event->update($data)`).  
* **Delete**: Menghapus data secara permanen dari tabel (`$event->delete()`).

#### 5.3.3. Route Resource

Untuk mempercepat pembuatan sekumpulan rute URL yang berkaitan dengan satu Controller khusus pengolahan data (seperti `index`, `create`, `store`, `edit`, `update`, `show`, `destroy`), Laravel menyediakan utilitas `Route::resource()`. Melalui eksekusi satu baris sintaks di `routes/web.php`, perintah tersebut secara instan menghasilkan 7 pola Route standar URL HTTP.

## **6\. PERTEMUAN 6 \- RELATIONSHIP ELOQUENT & FILTER DATA** {#6.-pertemuan-6---relationship-eloquent-&-filter-data}

### **6.1. Tujuan Instruksi Khusus** {#6.1.-tujuan-instruksi-khusus}

  ### **6.2. Alat dan Bahan** {#6.2.-alat-dan-bahan}

Alat dan bahan yang dibutuhkan pada praktikum ini sebagai berikut:

1. PC Desktop / Laptop  
2. Sistem Operasi Windows/Mac/Linux  
3. Aplikasi XAMPP / Laragon  
4. Visual Studio Code & Web Browser  
5. Terdapat sebuah proyek `laravel-app` yang melintasi fungsionalitas CRUD di Pertemuan 5\.

   ### **6.3. Dasar Teori** {#6.3.-dasar-teori}

#### 6.3.1. Relasi Eloquent (1:N)

Database relasional ditopang pada hubungan (relasi) antar dua tabel atau lebih. Pada desain *AmikomEventHub*, satu jenis *Category* dapat menampung banyak acara, sedangkan satu *Event* terhubung pada satu *Category*. Laravel mempermudah *mapping* relasi logis ini menggunakan *function* di dalam struktur Model:

* `hasMany()`: Ditempatkan pada Class Model induk (parent) yang terhubung ke banyak data anak (contoh: Class Category dihubungkan ke Event).  
* `belongsTo()`: Ditempatkan pada Class Model anak (child) yang merujuk pada satu *parent* tabel (contoh: Class Event dihubungkan balik ke Category).

#### 6.3.2. Eager Loading (N+1 Problem)

Ketika kita mengambil seluruh daftar `Event` dan melakukan perulangan (*looping*) lalu memanggil nama kategorinya, default Eloquent (disebut *Lazy Loading*) akan menjalankan 1 kueri `SELECT` untuk mengambil event ditambah kueri sebanyak "N" kali untuk mengambil identitas kategorinya secara berulang. Hal ini akan menurunkan performa sistem jika data event semakin banyak. Untuk mencegahnya, Laravel menyediakan teknik **Eager Loading** melalui method `with()`. Format implementasi: `$events = Event::with('category')->get();` Satu perintah baris ini akan mengambil kelengkapan data kategori secara efisien pada kueri awal tanpa ada perulangan panggilan ke database.

#### 6.3.3. Teknik Filtering

Filtering (Filter Data) merupakan mekanisme menyaring tampilan data dari database berdasarkan permintaan dari *klien* (biasanya disertakan dalam parameter url metode *GET* seperti `?category=seminar-it`). Kita dapat menggunakan logika kondisi klasik dalam antrean kueri atau menggunakan penyaringan relasional bawaan melalui `whereHas()`.

#### 9.3.1. Validasi Input (Form Validation)

Validasi adalah gerbang keamanan untuk memastikan bahwa data yang dikirim oleh pengguna (melalui form) sesuai dengan ekspektasi tipe, panjang, dan kewajiban isian. Di Laravel, validasi dapat dilakukan dengan sangat ringkas menggunakan `$request->validate()`. Mengunggah file (seperti gambar) tidak cukup hanya dengan menyimpan nama teksnya ke database. File fisiknya harus dipindahkan ke direktori aman di dalam server (folder `storage/app/public`). ## **PERTEMUAN 11 \- INTEGRASI MIDTRANS (SNAP)** {#pertemuan-11---integrasi-midtrans-(snap)}

### **11.1. Tujuan Instruksi Khusus** {#11.1.-tujuan-instruksi-khusus}

Setelah menyelesaikan praktikum ini, praktikan diharapkan dapat:

* Mendaftar dan melakukan penyiapan (Setup) akun Midtrans API untuk keperluan individu/pribadi.  
* Memasang *library* Midtrans PHP ke dalam lingkungan proyek Laravel.  
* Mengkonfigurasi parameter API (*Server Key*, Environment) secara aman.  
* Menghasilkan *Snap Token* transaksi untuk memunculkan antarmuka Jendela Pembayaran (Popup Midtrans) ke pelanggan.

  ### **11.2. Alat dan Bahan** {#11.2.-alat-dan-bahan}

Alat dan bahan yang dibutuhkan pada praktikum ini sebagai berikut:

1. PC Desktop / Laptop  
2. Koneksi Internet Aktif (Wajib untuk akses API luar)  
3. Aplikasi XAMPP / Laragon (Web Server & Database telah aktif)  
4. Visual Studio Code & Web Browser  
5. Proyek "AmikomEventHub" yang telah dipersenjatai Modul 10\.

   ### **11.3. Dasar Teori** {#11.3.-dasar-teori}

#### 11.3.1. Payment Gateway (Midtrans)

*Payment Gateway* merupakan entitas otoritas jembatan elektronik perantara yang secara aman menghubungkan platform E-commerce (Aplikasi kita) dengan berbagai kanal institusi finansial penyedia dompet pembayaran (Bank Transfer, Gopay, ShopeePay, dll). Midtrans adalah salah satu Payment Gateway dominan yang beroperasi secara resmi di Indonesia. Untuk mode simulasi *(Sandbox)*, ia tidak memotong dana bank sungguhan, hal ini sangat ideal digunakan pelajar ketika membangun purwarupa aplikasi kampus.

#### 11.3.2. Apa itu "Snap"?

Midtrans "Snap" merupakan jenis mekanisme integrasi *frontend*. Pada mode ini, tim pengembangan tidak perlu merancang rupa desain pilihan kanal bayar (seperti UI pemindai QR atau input kartu kredit) dari awal; sebab saat Midtrans menerima kunci keamanan API (*Snap Token*), mereka yang akan otomatis mengambil alih antarmuka *popup* jendela layar pilihan bayar secara mulus.

### **11.4. Instruksi Modul** {#11.4.-instruksi-modul}

#### 11.4.1. Mendaftar Akun Midtrans (Mode Personal)

Jika Anda mendaftar atas nama organisasi komersil, Midtrans membutuhkan verifikasi legalitas perseroan berlapis. Namun untuk keperluan riset belajar, mendaftar atas nama personal (pribadi) sudah cukup.

1. Kunjungi situs resmi pendaftaran: **midtrans.com**  
2. Lakukan pengisian Sign-Up dengan memasukkan nama lengkap, email, nomor telepon dan password.  
3. *Pada bagian Business / Bisnis:* Pilih tipe bisnis sebagai **Individu (Personal)** / Belum Berbadan Hukum. Nama bisnis isikan secara bebas dan unik.  
4. Lakukan pengecekan email aktivasi dan log masuk (*Login*) menuju layar Dashboard Midtrans (MAP / *Merchant Administration Portal*).  
5. Secara otomatis Anda akan memasuki lingkungan **Sandbox Mode**.

#### 11.4.2. Mengambil Akses Kunci API (Credentials)

Setelah terdaftar, berikan identitas koneksi *key* ke dalam variabel lingkungan `.env` aplikasi Anda.

1. Pada *Dashboard* Midtrans, klik menu **Settings** \> **Access Keys**.  
2. Salin isi `Server Key` dan `Client Key` dari *box* yang tersedia.  
3. Buka berkas pengaturan sentral `.env` di VS Code proyek  Anda. Tambahkan blok parameter berikut (Tempel hasil salinan Server Key Anda pada MIDTRANS\_SERVER\_KEY):

 `MIDTRANS_SERVER_KEY="SB-Mid-server-xxxx_xxxxxxxxxxxxxx"`

 `MIDTRANS_CLIENT_KEY="SB-Mid-client-xxxx_xxxxxxxxxxxxxx"`

 `MIDTRANS_IS_PRODUCTION=false`

4. Hubungkan pembacaan konfigurasi tersebut ke sistem pusat Laravel dengan membuat file konfigurasi mandiri. Buatlah sebuah file baru bernama `midtrans.php` di dalam folder `config/`.  
5. Buka `config/midtrans.php` dan isikan kerangka *array* pembacaan *environment* berikut:

`<?php`

`return [`

    `'server_key' => env('MIDTRANS_SERVER_KEY', ''),`

    `'client_key' => env('MIDTRANS_CLIENT_KEY', ''),`

    `'is_production' => env('MIDTRANS_IS_PRODUCTION', false),`

`];`

6. Bersihkan dan segarkan kembali memori *cache* konfigurasi proyek Anda agar sistem mendeteksi rincian data terbaru yang baru saja kita simpan:

`php artisan config:clear`

#### 11.4.4. Menghasilkan Snap Token Transaksi

Selanjutnya kita modifikasi kode fungsi rute simpang `store` (Checkout) yang sebelumnya kita biarkan menggantung tanpa tujuan (*return redirect('/')*). Kita harus memerintahkan Midtrans me-generate Token Pembayaran (Snap Token).

2. Ganti seluruh instruksi yang ada di bawah blok `// 4. Merekam Transaksi ke Database...` pada modul pertemuan 10 lalu dengan konfigurasi pemanggilan kelas dari API Midtrans:

        `\Midtrans\Config::$is3ds = true;`

            `'transaction_details' => [`

                `'order_id' => $orderId,`

                `'gross_amount' => $totalPrice,`

                `'phone' => $request->customer_phone,`

            `],`

        `];`

        `try {`

            `// Perintah Tembak Generate Snap Token`

            `$snapToken = \Midtrans\Snap::getSnapToken($params);`

            `// Redirect ke halaman antarmuka pembayaran final pelanggan`

   ### **12.3. Dasar Teori** {#12.3.-dasar-teori}

#### 12.3.1. Apa itu Webhook (Callback)?

Saat pengguna berhadapan dengan layar Popup Midtrans dan mereka menutup browsernya tiba-tiba setelah mentransfer uang via ATM, bagaimana sistem kita mengetahui bahwa uang tersebut sudah masuk? *Webhook* adalah solusinya. Begitu sistem pendeteksi bank internal Midtrans menyetujui mutasi uang masuk, peladen Midtrans akan diam-diam mengirimkan sebuah data notifikasi tipe POST "di belakang layar" *(Backend-to-Backend)* menembak URL peladen kita yang aktif (misal: `https://domain-anda.com/midtrans/callback`). Sistem kita yang tertidur seketika akan terbangun dan mengubah status rekaman database pembeli malang tersebut dari "Pending" menjadi "Success".

#### 12.3.2. Dashboard Panel

Dashboard adalah papan pantau utama (Control Center) tempat administrator meringkas dan menganalisis kesehatan usahanya dalam sekali pandang. Pada Laravel, pembuatan rekapitulasi numerik umumnya difasilitasi oleh query *aggregate* bawaan Eloquent SQL, misalnya perintah penjumlahan `sum()` dan perintah pencacahan `count()`.

### **12.4. Instruksi Modul** {#12.4.-instruksi-modul}

#### 12.4.1. Membuat Webhook Controller Midtrans

Kita membutuhkan *controller* baru yang tidak dikhususkan merender halaman *view*, namun murni menyerap data POST JSON (API Endpoint) dari mesin Midtrans.

1. Melalui jendela Terminal, cetaklah kerangka file Controller tersebut:

`php artisan make:controller MidtransWebhookController`

2. Buka `app/Http/Controllers/MidtransWebhookController.php` lalu isikan naskah kondisional yang berfungsi memfilter status *capture/settlement/cancel/expire*:

`<?php`

`namespace App\Http\Controllers;`

`use App\Models\Transaction;`

`use Illuminate\Http\Request;`

`class MidtransWebhookController extends Controller`

`{`

    `public function handle(Request $request)`

    `{`

        `$payload = $request->all();`

        `$orderId = $payload['order_id'] ?? null;`

        `$transactionStatus = $payload['transaction_status'] ?? null;`

        `$fraudStatus = $payload['fraud_status'] ?? null;`

        `if (!$orderId) {`

            `return response()->json(['message' => 'Invalid payload'], 400);`

        `}`

        `// Mencari ID transaksi tersebut di database lokal kita`

        `$transaction = Transaction::with('event')->where('order_id', $orderId)->first();`

        `if (!$transaction) {`

            `return response()->json(['message' => 'Transaction not found'], 404);`

        `}`

        `// Cegah proses berulang jika status sudah lunas/sukses`

        `if ($transaction->status === 'settlement' || $transaction->status === 'success') {`

            `return response()->json(['message' => 'Already processed']);`

        `}`

        `// Logika Penerjemahan Status Midtrans API`

        `if ($transactionStatus == 'capture') {`

            `if ($fraudStatus == 'challenge') {`

                `$transaction->status = 'challenge';`

            `} else if ($fraudStatus == 'accept') {`

                `$transaction->status = 'success';`

                `$this->processSuccess($transaction);`

            `}`

        `} else if ($transactionStatus == 'settlement') {`

            `$transaction->status = 'settlement';`

            `$this->processSuccess($transaction);`

        `} else if (in_array($transactionStatus, ['cancel', 'deny', 'expire'])) {`

            `$transaction->status = 'failed';`

        `} else if ($transactionStatus == 'pending') {`

            `$transaction->status = 'pending';`

        `}`

        `$transaction->save();`

        `return response()->json(['message' => 'OK']);`

    `}`

    `private function processSuccess(Transaction $transaction)`

    `{`

        `// Instruksi lanjutan saat transaksi lunas (pemotongan tiket) akan dibahas pada Modul 13`

    `}`

`}`

3. Buka konfigurasi alur URL di `routes/web.php` dan buat lubang *route POST* agar peladen Midtrans bisa menembak instruksi di atas secara bebas:

`Route::post('/midtrans/callback', [\App\Http\Controllers\MidtransWebhookController::class, 'handle']);`

4. **Penting (Konfigurasi Laravel 11/12/13):** Secara bawaan, Laravel mengaktifkan pelindung keamanan *CSRF Token* untuk semua rute POST. Karena notifikasi Webhook dikirim dari luar oleh peladen Midtrans (yang tidak memiliki token sesi lokal kita), sistem Laravel akan menolaknya (Error 419). Untuk melegalkan *(bypass)* rute `/midtrans/callback` dari pemblokiran tersebut, buka file konfigurasi inti `bootstrap/app.php` dan tambahkan rute tersebut ke rincian CSRF `except` di dalam blok `withMiddleware`:

 `->withMiddleware(function (Middleware $middleware) {`

     `$middleware->validateCsrfTokens(except: [`

         `'/midtrans/callback', // Mengecualikan route webhook Midtrans dari blokir CSRF`

     `]);`

 `})`

#### 12.4.4. Konfigurasi Webhook Midtrans & Pengujian via VS Code Port Forwarding

Agar peladen Midtrans dapat mengirimkan notifikasi *Webhook* menembus laptop Anda (yang berada di jaringan tertutup/lokal), Anda harus membuka "terowongan" (*tunneling*) ke internet terbuka. Kita bisa memanfaatkan fitur bawaan **VS Code Port Forwarding** secara gratis tanpa instalasi aplikasi seperti Ngrok.

**Langkah 1: Menyiapkan VS Code Port Forwarding**

1. Pastikan Proyek Anda menyala (misalnya perintah `php artisan serve` memegang port `8000`).  
2. Di jendela kerja **Visual Studio Code**, buka panel terminal di bawah layar, lalu pilih tab **PORTS** (biasanya bersebelahan dengan Terminal / Output / Debug Console).  
3. Klik tombol **Forward a Port**.  
4. Masukkan angka port server Anda, yaitu **8000** atau sesuai port yang kamu jalankan, lalu tekan Enter.  
5. Awalnya *Visibility* (Aksesibilitas) bersifat *Private*. Klik kanan pada port tersebut lalu ubah menjadi **Public**. (Sistem mungkin akan meminta Anda untuk log masuk ke akun GitHub/Microsoft Anda untuk menautkan sesi).  
6. VS Code otomatis akan menampilkan URL publik sementara (contoh: `https://xxxx-xxxx.asse.devtunnels.ms`). Salin (*Copy*) URL tersebut. Biarkan layanan tetap menyala di latar\!

**Langkah 2: Menghubungkan ke Dashboard Midtrans**

1. Log masuk ke [Dashboard Midtrans](https://dashboard.midtrans.com) (pastikan berada pada lingkungan operasi *Sandbox*).  
2. Pada bilah menu kiri, telusuri **Settings** \> **Configuration**.  
3. Temukan kotak isian **Payment Notification URL** (Ini adalah letak tujuan tembakan Webhook).  
4. Tempel (*Paste*) URL VS Code tadi, kemudian rangkai dengan akhiran rute webhook Anda. Contoh pengisian yang benar: `https://xxxx-xxxx.asse.devtunnels.ms/midtrans/callback`.  
5. Jangan lupa klik **Save** di sudut form tersebut.

**Langkah 3: Menguji Tembakan Webhook (Simulator)**

1. Midtrans menyediakan test simulator notifikasi. Jelajahi menu **Mock Notification** atau melalui dokumentasi API simulator mereka. (Alternatif terbaik: Murni jalankan ulang pembelian tiket dari halaman Checkout lokal Anda sampai lunas dengan nomor order baru).  
2. Coba lalukan simulasi transaksi, dan pada waktu pembayaran coba copy virtual account nya lalu tutup tab pembayaran. Lakukan pembayaran melalui simulator Midtrans lalu cek di dashboard apakah pembayaran sukses.

   ### **12.5. Latihan/Tugas** {#12.5.-latihan/tugas}

1. Terapkan secara berurutan kode-kode di atas ke dalam lingkup lingkungan IDE kode Visual Studio Code Anda.  
2. Silakan akses panel Admin Dashboard (`/admin/dashboard`), pastikan angka jumlah agregat tidak error, dan nominal Rupiah dari percobaan yang sudah di checkout sebelumnya muncul di sana. Ambil *Screenshot* halaman tersebut sebagai laporan keberhasilan UI Dasbor\!  
3. Lakukan pengujian Webhook menggunakan panduan **VS Code Port Forwarding** di atas. Buktikan bahwa usai Anda memicu pembayaran tuntas (baik lewat simulasi maupun popup sungguhan), indikator baris pesanan di Dasbor Anda otomatis tervalidasi sukses. #### 13.3.1. Pengujian Email dengan Mailtrap

Sistem pengiriman tiket (*E-Ticket*) selalu mengandalkan fungsi SMTP (*Mail Server*). Untuk menghindari risiko salah kirim atau pemblokiran spam oleh penyedia layanan seperti Google (karena status aplikasi masih dalam tahap pengembangan lokal), pengembang umumnya menggunakan layanan simulasi pengujian seperti **Mailtrap.io**. Mailtrap berfungsi untuk menangkap email yang dikirim dari *localhost* lalu menampilkannya di *inbox* virtual melalui antarmuka web mereka, sehingga tidak ada email yang benar-benar terkirim ke alamat email pengguna asli.

#### 13.3.2. Fitur Fallback Check

Walaupun sistem *Webhook* bisa diandalkan, jika aplikasi lokal tidak dapat diakses secara publik (tanpa menggunakan Ngrok atau *port forwarding*), notifikasi dari Midtrans tidak akan dapat masuk ke server lokal. Untuk mengatasinya, kita bisa memaksa pengecekan ulang status transaksi secara langsung menggunakan API `\Midtrans\Transaction::status()` saat pelanggan menutup tampilan pembayaran Midtrans dan mengklik tombol kembali yang mengarahkan mereka ke halaman *Success*.

### **13.5. Wawasan Industri: Menangani Race Condition pada Stok** {#13.5.-wawasan-industri:-menangani-race-condition-pada-stok}

Pada penulisan kode `processSuccess` sebelumnya, Anda mungkin menyadari adanya pengecekan `if ($event->stock > 0)`. Jika stok ternyata sudah habis padahal pembayaran berhasil, sistem kita saat ini hanya akan mencatat pesan peringatan (*warning*) ke dalam *log*. Mengapa hal ini bisa terjadi padahal sisa tiket selalu ditampilkan secara *real-time* di halaman utama?

Fenomena ini dikenal di dunia rekayasa perangkat lunak sebagai **Race Condition**. *Race condition* pada tiket terjadi ketika ada dua atau lebih pelanggan yang secara bersamaan membuka halaman *checkout* untuk memperebutkan 1 tiket terakhir, dan keduanya sama-sama sukses mendapatkan kode tagihan di jendela pembayaran Midtrans. Jika pelanggan A melunasi pembayaran beberapa detik lebih lambat dari pelanggan B, Midtrans akan tetap menyatakan pembayaran pelanggan A berhasil, namun kenyataannya tiket di *database* Anda sudah terlanjur dihabiskan oleh pelanggan B.

Di lingkungan industri teknologi skala besar (*Enterprise*), kendala perbutan ini umumnya ditangani melalui 3 alternatif:

1. **Penanganan Manual (Log Monitoring):** Sesuai dengan batasan kode modul kita saat ini, sistem hanya mencatat anomali tersebut di `storage/logs/laravel.log`. Admin bertugas mengecek *log* ini secara berkala, kemudian memproses pengembalian dana (*Refund*) secara manual dari *Dashboard Midtrans* kepada pelanggan A.  
2. **Automated Refund (Pengembalian Otomatis via API):** Memodifikasi sistem *backend* agar langsung mengeksekusi [API Refund Midtrans](https://docs.midtrans.com/reference/refund-transaction) ketika mendeteksi `stock <= 0` pada saat notifikasi Webhook masuk. Uang pelanggan otomatis dikembalikan tanpa campur tangan staf admin.  
3. **Sistem Booking / Reserved Stock (Pencegahan di Awal):** Ini adalah standar praktik terbaik (*best practice*) yang diadopsi oleh platform penjualan tiket modern. Sistem tidak akan menunggu sampai pelanggan mentransfer uang untuk mengurangi kuota. Sebaliknya, di detik saat pelanggan menekan tombol "Bayar Sekarang", sistem langsung mengunci sementara (*reserve*) 1 tiket tersebut. Jika dalam tenggat waktu masa tenggang pembayaran (misal 15 menit) dana belum dilunasi, barulah sistem melepaskan kembali (+1) tiket itu agar dapat dibeli oleh pengunjung lain.

   ### **13.7. Persiapan Deployment (Lingkungan Production)** {#13.7.-persiapan-deployment-(lingkungan-production)}

Sebagai wawasan pelengkap, jika Anda berencana mempublikasikan aplikasi ini ke ranah *Production* (dapat diakses publik secara komersial di internet), berikut adalah beberapa hal krusial yang harus disiapkan:

1. **Pemilihan Layanan Hosting / VPS:** Aplikasi Laravel modern membutuhkan *Cloud VPS* (Virtual Private Server) atau *Shared Hosting* yang memiliki akses Terminal/SSH, fitur *Composer*, dan mendukung versi PHP terbaru.  
2. **Konfigurasi Domain dan SSL (HTTPS):** Anda wajib memiliki nama domain resmi dan mengaktifkan sertifikat enkripsi SSL. Keamanan ini mutlak diperlukan; terlebih sistem Midtrans sangat mewajibkan URL *Webhook* menggunakan koneksi `https://` pada mode transaksi uang nyata.  
3. **Penyesuaian File Environment (`.env`):**  
   * Ubah `APP_ENV=local` menjadi `APP_ENV=production`.  
   * Ubah `APP_DEBUG=true` menjadi `APP_DEBUG=false` agar detail *error* kerangka program tidak bocor ke layar pengunjung.  
   * Pastikan `APP_URL` diisi dengan alamat domain rilis Anda.  
4. **Peralihan Kredensial Midtrans (Uang Asli):**  
   * Ganti `MIDTRANS_SERVER_KEY` dan `MIDTRANS_CLIENT_KEY` Anda dari mode uji coba (*Sandbox*) menjadi kunci *Production*. Kunci rilis ini baru bisa diterbitkan oleh Midtrans setelah Anda menyerahkan kelengkapan dokumen legalitas identitas/bisnis.  
   * Ubah status *environment* `\Midtrans\Config::$isProduction` dari `false` menjadi `true`.  
   * Anda harus menautkan ulang arah alamat **Payment Notification URL** di Dashboard Midtrans (pada mode *Production*) menuju nama domain asli Anda.  
5. **Konfigurasi Server SMTP Email Nyata:** Ingat, layanan Mailtrap hanya digunakan untuk simulasi *developer*. Di lingkungan rilis, Anda harus menggunakan kredensial SMTP yang sah untuk meneruskan *E-Ticket* ke kotak masuk pengunjung (misalnya menggunakan SMTP Webmail bawaan cPanel, Brevo, Mailgun, atau Amazon SES).  
6. **Optimasi Kinerja Laravel:** Jalankan perintah *caching* di *server* target agar konfigurasi, rute, dan antarmuka aplikasi merespons secara kilat:  
   * `php artisan optimize`  
   * `php artisan view:cache`  
7. **Migrasi dan Keamanan Database:** Konfigurasikan koneksi basis data rilis Anda di `.env`, jalankan `php artisan migrate` dengan hati-hati (hindari perintah `fresh` atau `rollback` yang akan menyapu bersih data pelanggan asli), serta siapkan jadwal pencadangan (*Backup*) berkala.  
8. **Alternatif Modern dengan Laravel Cloud:** Sebagai opsi *hosting* terpadu yang sangat direkomendasikan, Anda dapat mempertimbangkan platform **Laravel Cloud** ([https://laravel.com/cloud](https://laravel.com/cloud)). Layanan infrastruktur resmi dari pencipta Laravel ini dirancang khusus untuk mempermudah proses *deployment* dan skalabilitas (*auto-scaling*) aplikasi Laravel secara otomatis tanpa memerlukan keahlian konfigurasi *server* atau DevOps yang rumit.

   ### **13.8. Ruang Lingkup & Saran Pengembangan (Tugas Akhir)** {#13.8.-ruang-lingkup-&-saran-pengembangan-(tugas-akhir)}

Aplikasi *AmikomEventHub* yang Anda bangun dalam praktikum ini hanyalah prototipe dasar (*Minimum Viable Product*). Untuk menjadikannya sistem berskala industri (*Enterprise Grade*) yang sangat layak diangkat sebagai instrumen Tugas Akhir atau dikomersialkan secara nyata, berikut adalah **10 contoh ide pengembangan** yang dapat Anda aplikasikan:

1. **Integrasi Notifikasi WhatsApp & *Abandoned Cart Recovery*:** Mengirim E-Ticket melalui email sudah cukup memadai, namun notifikasi via WhatsApp (menggunakan API seperti Fonnte, Wablas, atau Twilio) akan sangat menyempurnakan pengalaman pengguna di Indonesia. Anda juga bisa membangun fitur pemulihan pesanan: jika pembeli tidak sengaja menutup tab *browser* sebelum membayar, sistem akan otomatis mengirimkan pesan berisi *link* pembayaran Midtrans ke WhatsApp agar transaksi mereka tidak hangus.  
2. **Arsitektur Multi-Tenant (Banyak Organisasi/Kepanitiaan):** Mengembangkan aplikasi dari "Satu Toko" menjadi *Platform SaaS* layaknya *marketplace*. Modifikasi skema *database* agar setiap Kepanitiaan/HIMA dapat membuat akun, mengelola acara sendiri, dan melihat analitik pendapatan di *Dashboard* khusus mereka. Sementara *Superadmin* bertugas mengawasi kelayakan seluruh penyelenggara.  
3. **Penyempurnaan Penanganan Stok (Reserved Ticket):** Meningkatkan penanganan *Race Condition* ke standar *best practice*. Jangan menunggu pembayaran lunas untuk mengurangi stok. Alih-alih begitu, sesaat setelah pengunjung mengeklik tombol Checkout, langsung "tahan" (*reserve*) stok tiket tersebut. Jika pembayaran *expired* (misal 15 menit), sistem akan melepaskan tiket (+1) agar dapat direbut pembeli lain.  
4. **Bypass Transaksi untuk Acara Gratis (Free Events):** Ciptakan percabangan logika khusus; jika harga tiket acara diatur `Rp 0`, sistem akan membypass alur Midtrans. Pembeli langsung diarahkan ke rute sukses, E-Ticket langsung dicetak, dan stok dikurangi saat itu juga.  
5. **Sistem Aplikasi Penjaga Pintu (*Check-in Scanner*):** Merupakan pelindung anti-kecurangan yang krusial. Rancanglah halaman web terpisah berbasis *HTML5 QR Scanner* (memanfaatkan kamera handphone) yang dipakai khusus oleh panitia registrasi di hari-H. Saat kode QR peserta di- *scan*, sistem akan mengecek silang dan mengubah status tiket menjadi `used` agar tidak bisa dipakai oleh penyusup (*double entry*).  
6. **Penerbitan E-Certificate Kehadiran Otomatis:** Fitur primadona untuk *event* bernuansa seminar atau lokakarya (*workshop*). Sesaat setelah acara berakhir (atau dipicu dari *scan* validasi kehadiran), sistem akan merender desain sertifikat PDF berisikan nama spesifik peserta yang bersangkutan, kemudian melayangkannya langsung ke email mereka.  
7. **Sistem Ulasan dan Penilaian Bintang (Rating & Review):** Menumbuhkan ekosistem pasca-acara yang interaktif. Bangun mekanisme penagihan *rating* (1-5 bintang) dan testimoni sehari setelah acara tuntas. Tampilan rekam jejak penilaian ini nantinya ditayangkan di halaman profil penyelenggara guna menarik kepercayaan calon pembeli di acara mereka selanjutnya.  
8. **Login Instan via Sosial Media (SSO):** Memangkas tahap pembuatan akun secara drastis menggunakan *library* **Laravel Socialite**. Izinkan pengguna melewati kerumitan form pendaftaran, cukup dengan sekali klik menggunakan tombol *"Continue with Google"* untuk memesan tiket.  
9. **Strategi Dynamic Pricing & Kode Kupon (Voucher):** Susun sistem pemasaran fleksibel di mana pembeli dapat menukarkan kode seperti `MAHASISWA50` untuk menerima irisan diskon harga. Tingkatkan juga model penjualan bertahap; contohnya memisahkan tiket kategori *Early Bird*, *Presale 1*, hingga *Regular* yang rentang harganya naik secara otomatis seiring bergantinya tanggal.  
10. **Peningkatan Menjadi Progressive Web App (PWA):** Sulap halaman *website AmikomEventHub* menjadi "Aplikasi HP" murni.
